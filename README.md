# 김건희 개인 브랜딩 아카이브

기존 에디토리얼 디자인에 이야기·능력 근거·기록·대표작·문서의 상세 모달을 연결한 Next.js + TypeScript 프로젝트입니다. 닫기 버튼, Escape, 초점 복귀, 모달 내부 스크롤을 지원합니다. 모달의 도형 이미지는 장면을 나타내는 삽화이며 실제 사진이 아닙니다.

## 실행과 확인

Node.js 20.9 이상에서 `npm ci`, `npm run dev`를 실행하고 http://localhost:3000 을 엽니다. `npm test`와 `npm run build`로 검증합니다. 정적 결과는 out/에 생성됩니다. next start를 사용하지 않습니다.

## 자료 상태

9번 확정 서사와 ritual-history-2026-10-01.json을 찾아 본인 이름, 2018년 스마트 미러 경험과 2026년 실제 장면을 연결했습니다. 자기소개 약 1,400자는 새 편집안이며 최종 확인이 필요합니다. 첫·마지막 문장은 2026-10-07 확정 자기소개서에서 유지했습니다. 11번 소설에서 추출한 것으로 표시하지 않았습니다.

원본 기록일 34일, 월요일 시작 기준 8개 주, 확보 기간 2026-08-11~2026-10-01. 공개 장면은 여섯 개입니다. 원본 전체와 타인의 이름은 저장소에 포함하지 않았습니다. 출석과 제출 현황은 별도 자료 미확보로 null이며 —로 표시합니다. 13주 전체 기록이 확보됐다는 뜻이 아닙니다.

공개 연락 수단은 GitHub 공개 프로필의 이메일을 연결했고, 10번 논문 통합 초안을 사이트에 직접 올렸습니다. 이력서·자기소개서·경력기술서는 DOCX로 다운로드됩니다. 11번 소설 원문, 13주 전체 출석·제출 원본, 13번 앱 확정 예정일은 자료가 없어 추정하지 않았습니다.

## 기록 갱신

**README-refresh.md**의 세 단계로 숫자와 능력별 날짜/근거 문단 후보를 만들고 선택한 후보만 승인하여 반영합니다. 초기 결과에는 새 후보 승인 문단이 없습니다. 기존 records:* 명령은 기록만 갱신하는 이전 방식이며 최신 숫자와 후보 갱신에는 refresh:* 명령을 사용하세요.

## 파일 위치

- app/Detail.tsx: 모든 상세 모달과 도형 이미지
- data/profile.json: 이름, 소개, 날짜별 이야기, 대표작 상태
- data/generated.json: 숫자와 승인 문단
- inputs/: 원본에서 정리한 공개용 입력
- public/documents/: 이력서, 자기소개서, 프로젝트 경험 기술서, 출처, 마지막 결과, 제출 확인 방법, 갱신 장치 ZIP
- scripts/refresh.mjs: 후보 생성·승인·반영

## GitHub Desktop

File → Add Local Repository에서 이 프로젝트 폴더를 선택합니다. origin은 https://github.com/GunHeeKim127/ritual-portfolio.git 에 연결되어 있습니다. Changes에서 수정된 본문/자료/파일을 확인해 Commit to main 후 Push origin을 사용합니다. 원격을 새로 만들 때만 Publish Repository를 사용합니다. 코드 업로드와 웹 배포는 별개입니다.

main 브랜치에 푸시하면 GitHub Actions가 테스트와 정적 빌드를 거쳐 GitHub Pages에 배포합니다. 공개 주소는 https://gunheekim127.github.io/ritual-portfolio/ 입니다.

## 제출 전 확인

public/documents/submission-check.md에 위치 안내와 실제로 확인된 AI·사용자 역할을 적었습니다. 본인의 최종 판단, 동료 반응, 공개 배포 및 새 시크릿 창 접근 확인은 완료하지 않은 것으로 표시합니다. 실제 개인정보/비밀값은 입력 및 승인 시 직접 점검해야 합니다.
